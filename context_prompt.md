### Architecture: 2 LangGraph agents + deterministic tools

**Key insight that shaped everything**: guardrails must be deterministic Tools, not LLM Agents — sending a query to an LLM just to check if it's safe to send to an LLM is self-defeating. Same principle Stage 3b already used (regex, not LLM). This drove reducing from an initial 4-5 agent idea down to 2.

**Agent 1 — Transform + Route** (one agent, one call per sub-query for routing):
- Decomposes compound questions into sub-queries (dynamic count, LLM-decided) + generates up to **3** phrasing variants per sub-query (expansion) — both together, capped to bound cost.
- Routes **per sub-query** (not once for the whole question — mixed questions like "which papers use YOLOv11 and what's its performance" need different routing per sub-part). Outputs: `needs_retrieval` (if false → general-knowledge answer, **must be labeled "not from the knowledge base, AI-generated"**), `data_source` (vector/graph/both), `search_mode` (simple/hybrid — **vector-only**; graph "hybrid" was considered and explicitly rejected — the graph has no semantic signal to combine with anything, entities are exact-name-matched not embedded), `images_required` (independent flag, judged on visual intent — resolved via existing graph `Image-[:NEAR_SECTION]`/`APPEARS_IN` relationships scoped to whatever sections the main retrieval touched, no new infrastructure needed).
- On retry, receives **structured feedback** from Agent 2 (what was missing + what to look for) and re-routes informed by it — not a blind retry.

**Agent 2 — Quality Check + Generate**: judges retrieved results; if sufficient, generates directly (inline per-claim citations); if not, triggers the retry sequence below instead of generating immediately.

**Retry policy (max 3 attempts total, no infinite loop risk)**: attempt 1 = normal retrieval → attempt 2 = Reranker (`BAAI/bge-reranker-base`, local/free, same family as `bge-base-en-v1.5`) → attempt 3 = Agent 2 sends feedback, Agent 1 re-routes informed by it → if still insufficient after 3, generate best-effort answer with a transparency caveat ("retrieval confidence was low").

**Combining `both` results**: text narrowing via graph-filtered paper list works well for complex/decomposed queries (graph finds papers, vector search scoped to just those). **Does NOT apply to images** — a paper matching an entity doesn't mean all its images are about that entity; images stay a separate unnarrowed lookup via existing graph relationships.

**Caching — Postgres only, NOT Neo4j** (graph caching was proposed, discussed honestly, and rejected as the primary mechanism — Neo4j is built for relationship traversal, not fast point lookups, so it would make the cache check slower than what it's meant to speed up; the good instinct behind it — query/chunk/answer lineage — is preserved by just logging everything to the same Postgres table instead). Flow: `Input Guardrail (redact PII FIRST, before anything else touches the query) → Cache Check #1 (raw query) → [HIT: return] / [MISS: Agent 1] → Cache Check #2 (transformed query) → [HIT: return] / [MISS: Retrieval → Agent 2 → Cache/Log Writer, stores under both query keys]`.

**Prompt caching (Gemini-side, provider-level)**: verified via web search — costs $0.15/1M tokens read + $1.00/1M tokens/hour storage, no confirmed free tier. Initially decided to skip, but **user's counter-argument won**: since it's an explicit `cachedContents.create` API call (not a flag), just **attempt it and catch failures, falling back to normal uncached generation** — costs nothing extra if unavailable (one failed API call, negligible), saves money automatically if it ever becomes available. **Final decision: implement with try/fallback pattern**, not skipped.

**Framework: LangGraph** (confirmed) — fits the explicit, ordered multi-node structure (fixed sequencing like "cache check always first") better than a free-form single ReAct agent would.

**Output Guardrails' grounding check**: reuses the exact "verify entity text appears in source" pattern already built and proven in Stage 6b's entity extraction — codeable, not an agent, same principle as Input Guardrails. **Implemented** as `verify_citations()` in `output_guardrail.py`.

**Prompt caching: GAP NOW CLOSED — implemented, tested, and live-verified.** User asked "why skipping prompt caching fallback, implement it" — built `call_with_cache()` in `gemini_retry.py` (attempts `client.caches.create()` once per distinct instruction, remembers success/failure, falls back cleanly).
